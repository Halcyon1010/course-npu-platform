# 资源接口 v0.1（联调草案）

课程平台是客户端，算力 TA 提供 HTTP 服务。一个作业最多使用 1 张卡，分配和启动是同一操作。学生身份、每人一个活跃申请和 FIFO 等待队列由课程平台管理。服务端独立保证设备互斥。模拟器仅监听本机，真机接入前双方需配置 HTTPS、服务身份和私有制品访问权限。

| 请求 | 成功响应 | 语义 |
| --- | --- | --- |
| `GET /v1/capacity` | 200，例 `{"total":2,"free":1}` | 读取当前可调度容量和空闲量。 |
| `PUT /v1/jobs/{id}` | 新建 201，重试已有作业 200 | 调度器给出全局唯一 ID。只有设备可用时才接受新作业。 |
| `GET /v1/jobs/{id}` | 200，返回作业 | 未知 ID 返回 404 和错误码 `unknown_job`。 |
| `DELETE /v1/jobs/{id}` | 200，返回当前作业 | 可重复取消。未知 ID 也记录为已取消，延迟到达的 PUT 不会重新启动作业。 |

**派发请求**使用 `Content-Type: application/json`，格式如下。

```json
{"cards":1,"artifact_id":"art-demo","runtime":"course-base"}
```

- `id` 由 1–80 个英文字母、数字、下划线或短横组成。生产使用平台生成的 UUID。
- `artifact_id` 为平台私有代码包标识，允许同一字符集，长度 1–128。真实资源端以服务身份解析，模拟器只校验格式。
- `runtime` 可为课程镜像别名 `course-base`，或已构建镜像的摘要 `sha256:<64 位小写十六进制>`。真实资源端从双方配置的受信仓库解析摘要；课程镜像应在建单时记录具体版本。
- `cards` 必须为整数 1。字段缺失、额外字段或无效值返回 400。请求体上限为 8 KiB。

**作业响应**始终带有以下字段，未产生的制品编号为 `null`。

```json
{"id":"demo-01","status":"succeeded","log_id":"log-demo-01","result_id":"result-demo-01"}
```

模拟器返回 `running`、`succeeded` 或 `cancelled`。真实资源端还需支持 `cancelling` 和 `failed`；失败原因随日志返回。所有终态表示设备已清理并释放。成功前须完成结果持久化。日志及结果通过平台鉴权后读取；模拟器返回的编号仅用于联调，不对应真实文件。

**重试处理**。满载时返回 409 和 `{"error":"no_capacity"}`，此时尚未创建记录，平台保留队列位置。同一 ID 和相同参数重复派发始终返回已有记录；同一 ID 改参数返回 409 和 `{"error":"id_conflict"}`。网络超时先查询作业，再决定是否原样重试。取消与完成竞态以最先确认的终态为准。真机适配器须持久保存作业和取消记录，具体保留期须覆盖平台重试窗口。
