# 课程算力平台建设方案

## 首版范围

目标是让每个学生用课程账号运行自己的项目，并通过网站取回结果。平台按作业分配卡，学生在提交时申请，运行结束即释放。这样无需逐人开机器账号或人工转发输出。

| 来自讨论的需求 | 首版处理 |
| --- | --- |
| 聊天中提到待对接的 64 张卡 | 管理页从资源接口读可调度卡数、空闲卡数和最后更新时间。接口不可达时显示“资源状态未知”。 |
| 每个学生可能选不同模型、依赖不同 | 统一提交规范，允许课程镜像与自定义 Dockerfile 两种提交方式。 |
| 有项目可能需要 4 卡 | 按当前要求固定每生 1 卡。保留资源需求字段，首版校验值只能为 1。 |
| 代码在裸金属 NPU 运行，结果返回给学生 | 平台持有作业编号、状态和产物索引，由算力 TA 的执行器负责设备分配、容器运行和回收。 |

## 学生如何使用

1. **登录**。TA 导入选课名单并开通账号，学生首次登录设置密码。校园统一身份认证可在校方提供接口后接入，同一学号始终映射到同一学生记录。
2. **准备提交包**。标准路径是上传一个 ZIP，根目录含代码与 `run.sh`，选择课程镜像。自定义路径在同一份包的根目录增加 `Dockerfile`。两条路径都从项目根目录执行 `bash run.sh`，将结果写入 `/outputs`。课程发布一个最小可运行样例并标明包大小、超时和输出限额。
3. **申请一张卡并运行**。页面显示提交摘要、镜像选项与申请卡数。提交后立即返回任务号。自定义镜像先在隔离的构建节点构建和校验，通过后入队；无卡时显示排队状态，无需重复申请。
4. **查看与取回**。“我的任务”显示排队、运行、取消中、完成或失败，详情页展示日志、失败原因和结果下载。学生可以取消自己的任务，平台按学号校验访问权限。

## 组件和数据

建议首版使用 **Django + PostgreSQL + S3 兼容对象存储**。Django 的账号、会话与管理后台覆盖课程管理需求，前台使用服务端模板。单独的调度进程从数据库领取作业，通过 HTTPS 调用资源服务。学生凭据、提交的项目、日志和输出放在私有运行环境中。GitHub 保存平台源代码、模板、接口和测试。

| 组件 | 负责的事 |
| --- | --- |
| 学生网页和平台 API | 登录、上传、建单、取消、查询本人任务、授权下载。浏览器只访问平台。 |
| TA 后台 | 导入名单、管理课程镜像、查看队列和设备容量、定位失败、取消异常作业。 |
| 数据库与调度器 | 保存学生、镜像版本、作业、状态事件、制品元信息与重试时间。任务变更和待派发记录在同一事务中写入。 |
| 对象存储与构建节点 | 私有保存输入、日志和输出。隔离构建自定义镜像并记录摘要，向资源侧按作业授权读取。 |
| 资源服务（算力 TA） | 报告容量、接受单卡任务、启动容器、写出日志和结果、确认设备清理完毕。设备型号、节点地址和调度实现由该服务封装。 |

### 单卡规则与异常恢复

- 每人最多一个未结束申请，覆盖待构建、排队、派发中、运行和取消中。在数据库对活跃作业的 `student_id` 建条件唯一索引，用事务处理并发提交。前端禁用按钮只改善体验。结束后可再次申请。
- 构建通过的作业按进入就绪队列的时间排序。同一份申请始终使用同一个平台作业 ID。调度器以带过期时间的领取记录协调多个进程，远端调用超时先查同一 ID，再按原 ID 重试。
- 容量读数用于展示，分配结果以派发接口为准。无卡时保留原排队顺序并退避重试。网络中断时标记状态待同步，保留学生配额，直到算力侧确认终态和设备已释放。
- 取消已派发任务时写入取消意图，持续对账到远端确认结束。为处理取消早于派发抵达的情况，资源端按作业 ID 保留取消记录。运行超时同样走终止与清理流程。
- 上传解包限制大小、路径和文件数。容器使用非特权用户，限制 CPU、内存、磁盘、网络和运行时长，仅映射分配的设备。构建与执行环境均不向学生项目暴露宿主凭据、容器管理套接字或其他学生目录。

## 实施顺序与验收

| 阶段 | 交付 | 验收场景 |
| --- | --- | --- |
| 1 · 约定接口 | 本仓库的协议与模拟资源端 | 没有硬件也能演示派发、满载、查询、重试与释放。 |
| 2 · 做通学生流程 | 学生端、TA 后台、数据存储、调度进程和课程基础镜像模板 | 两个账号竞争一张模拟卡，先到先运行；同一学生在两个窗口同时提交仅产生一个活跃申请；他人无法下载结果。 |
| 3 · 真机联调 | 算力 TA 实现相同协议，接入构建、日志和产物存储 | 用一个基础镜像项目和一个自定义 Dockerfile 项目各跑一次单卡 NPU 任务，验证故障、取消、重启后对账和结果下载。 |
| 4 · 课程开放 | 初始名单、运行限额、备份与故障处置 | 按实测容量压测排队与回收，验证真实硬件可用、告警可达，产物到期可清理。 |

**真机联调前需确认**：卡型、拓扑、每卡可独立分配的设备单位、可用数量、驱动及 CANN / PyTorch 兼容版本、镜像仓库、制品传输网络与服务鉴权。课程侧确定身份源、作业时限、提交包上限、产物保留期及是否允许拉取外部模型。基础镜像应通过真机样例后固定版本与摘要。
